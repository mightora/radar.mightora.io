## Existing behavior and findings

- Example loading uses `window.prompt()` with free-text lookup against the `EXAMPLE_FILES` map; the replace confirmation is present when dirty.
- `loadShared()` is defined but not called. A valid generated v1 `#/view/` URL was opened in the local browser; its distinct `Shared Check` CSV did not load and the Editor panel remained visible. This pre-existing defect is tracked by D-05; no fix is included in F00.
- The header Examples link targets `#examples`, but the page has no matching element (`document.querySelectorAll('#examples').length` was `0`).
- The Documentation toolbar button calls `window.open()` with `https://github.com/mightora/radar.mightora.io`; no user guide exists.
- The `<head>` contains title, viewport, theme color, and the required footer fetch patch. It has no description, canonical, Open Graph, structured data, `robots.txt`, or `sitemap.xml`. The app updates the `pageTitle` `<h1>` from the current radar name.
- `scripts/smoke-test.mjs` checks source text and sample CSV/config values; it does not exercise application behavior or a browser.
- `scripts/build.mjs` copies only `index.html`, `src/`, and `public/` into `dist/`; future root guide/robots/sitemap assets need explicit build handling.
- Existing CSV parsing, 300 ms debounced validation, last-valid preview, undo/redo, upload/download, share privacy warning, five exports, print view, and shared Mightora components were observed in source. Their full behavior is not claimed verified by source inspection.
- The built local app loaded with 17 valid technologies; its runtime `<h1>` showed `Power Platform Radar`. The browser observed no description or canonical metadata. One request to `http://localhost:8080/data/config.json` returned 404; the app, author and footer rendered. The request owner and production impact were not determined.
